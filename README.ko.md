# NoMenu

[English](README.md) | **한국어**

NoMenu는 메뉴 막대에 사용할 수 있는 공간이 부족해 접근할 수 없게 된 항목을 다시 사용할 수 있도록 만든 macOS 유틸리티입니다. 손쉬운 사용 API를 통해 실제 상태 항목을 찾고, 오버플로된 것으로 확인된 항목만 자체 메뉴 막대 패널에 표시합니다.

> [!IMPORTANT]
> NoMenu는 macOS 27 이전 버전의 메뉴 막대 동작을 기반으로 만들어졌습니다. macOS 27에는 시스템 자체의 메뉴 막대 오버플로 처리가 도입되어 NoMenu가 의존하던 동작이 달라졌습니다. 따라서 macOS 27 이상은 지원하지 않으며, 해당 버전을 위한 기능 개발도 현재 계획되어 있지 않습니다.

## 다운로드

현재 공개된 DMG는 없습니다.

> 미리 빌드된 DMG가 준비되면 [GitHub Releases](https://github.com/Rotear001/NoMenu/releases)를 통해 배포합니다. 이 페이지가 공식 다운로드 위치입니다.

향후 릴리스를 다운로드하기 전에 호환성을 확인해 주세요. NoMenu는 이전 macOS 버전을 대상으로 하며, 시스템 자체의 메뉴 막대 오버플로 처리로 인해 동작 방식이 달라진 macOS 27 이상은 지원하지 않습니다.

## 프로젝트 상태 및 호환성

NoMenu는 소스 코드만 공개된 유지 관리·마무리 단계의 프로젝트입니다. 현재 공개된 미리 빌드된 바이너리는 없습니다.

| 항목 | 지원 범위 |
| --- | --- |
| 배포 대상 | macOS 15.0 |
| macOS 15–26 | NoMenu가 대상으로 삼은 기존 메뉴 막대 동작 범위 |
| macOS 27 이상 | 지원하지 않음 |

배포 대상 버전은 `Package.swift`와 `Support/Info.plist`에서 확인한 값입니다. 이는 빌드 대상의 하한을 뜻하며, macOS 15–26의 모든 버전과 모든 메뉴 막대 구현을 개별적으로 검증했다는 의미는 아닙니다.

## 기능

- 실행 중인 앱이 손쉬운 사용 API로 노출하는 메뉴 막대 항목을 찾습니다.
- 손쉬운 사용 요소의 위치, 디스플레이 안전 영역, 현재 앱 메뉴가 차지하는 범위, 화면에 표시된 컴포지터 정보를 함께 사용해 항목을 표시됨, 오버플로됨, 확인 불가 상태로 분류합니다. 오버플로가 확인된 항목만 표시합니다.
- 지원되는 항목은 손쉬운 사용 동작을 통해 제어합니다. 읽을 수 있는 메뉴 트리가 있으면 NoMenu가 네이티브 프록시 메뉴를 표시하고 실제 메뉴 동작을 실행합니다.
- 패널에서 항목을 사용하는 동안 다른 항목으로 바로 전환할 수 있습니다.
- 메뉴 막대 순서, 최근 사용 순서 또는 이름순으로 항목을 정렬할 수 있습니다.
- 무시할 항목 관리, 전역 키보드 단축키, 포인터 오버 동작, Escape 키로 닫기, 항목 실행 뒤 패널 유지 옵션을 제공합니다.
- 패널 위치, 너비, 크기, 간격, 배경, 흐림, 투명도, 인터페이스 크기, 애니메이션과 영어·한국어 UI를 설정할 수 있습니다.
- `SMAppService`를 사용해 로그인 시 실행을 관리합니다.
- 프레임 속도를 설정할 수 있는 ScreenCaptureKit 기반 Live Artwork와 앱 아이콘 대체 표시를 제공합니다. Live Artwork는 화면 캡처 권한과 캡처 가능한 화면 픽셀에 따라 달라지는 기능입니다.

## 권한

### 손쉬운 사용

메뉴 막대 항목을 찾고, 해당 항목이 노출하는 메뉴 구조를 읽고, 지원되는 동작을 실행하려면 손쉬운 사용 권한이 필요합니다. 실제 동작은 각 타사 앱이 손쉬운 사용을 통해 제공하는 정보와 동작에 따라 달라집니다.

### 화면 및 시스템 오디오 녹음

화면 녹화 권한은 Live Artwork와 선택적 패널 모양에 쓰이는 데스크탑 배경 픽셀을 캡처하는 데 사용됩니다. 권한이 없으면 가능한 경우 캐시된 아트워크 또는 항목을 소유한 앱의 아이콘을 대신 표시합니다.

메뉴 막대 검색, 캡처한 아트워크 처리, 환경설정 저장은 Mac 안에서 이루어집니다. NoMenu 사용에 계정은 필요하지 않습니다. 현재 개발 빌드에는 업데이트 서비스 백엔드가 연결되어 있지 않습니다.

## 소스에서 빌드하기

NoMenu는 Swift 6 및 Swift Package Manager로 빌드한 뒤 셸 스크립트로 `LSUIElement` 앱 번들을 구성합니다. 호환되는 macOS SDK가 포함된 Xcode Command Line Tools 또는 Xcode가 필요합니다.

```sh
git clone https://github.com/Rotear001/NoMenu.git
cd NoMenu
./scripts/build-app.sh release
```

패키징에 성공하면 `build/NoMenu.app`이 생성됩니다. `debug` 인자도 사용할 수 있습니다. 두 인자는 Swift 최적화 설정을 선택할 뿐이며, 결과물은 모두 로컬 개발 빌드입니다.

이 소스 스냅샷은 Apple Swift 6.4 및 macOS 27 SDK 환경에서 빌드 검증을 완료하지 못했습니다. 수정하지 않은 소스의 `Sources/NoMenu/Views/SettingsView.swift`에서 컴파일 오류가 발생합니다. 다른 도구 체인을 사용한 깨끗한 빌드는 검증되지 않았으며, 저장소 공개 작업에서는 애플리케이션 소스를 의도적으로 수정하지 않았습니다.

## 개발용 코드 서명

개발 과정에서는 로컬에서 다시 빌드해도 macOS 개인정보 보호/TCC 식별 정보를 안정적으로 유지하기 위해 **NoMenu Local Code Signing**이라는 자체 서명 코드 서명 인증서를 사용했습니다. 해당 인증서와 개인 키, 컴퓨터별 설정 파일인 `Support/DevelopmentSigning.conf`는 저장소에 포함되지 않습니다.

패키징 스크립트는 지정된 로컬 서명 ID를 찾지 못하면 의도적으로 중단됩니다. 저장소를 복제한 기여자는 이 개발용 서명 ID를 갖고 있지 않으므로 앱 번들을 만들기 전에 자신의 로컬 환경에 맞게 서명을 설정하거나 빌드 절차를 조정해야 합니다. 서명 ID가 달라지면 macOS가 개인정보 보호 권한을 기준으로 빌드를 다른 앱으로 인식할 수 있습니다.

이 자체 서명 인증서는 로컬 개발 전용입니다. 향후 공개 바이너리를 배포하려면 Developer ID 서명 및 공증과 같은 적절한 별도 배포 절차가 필요합니다. 로컬 인증서를 가져오거나 공유하거나 공개 배포에 사용해서는 안 됩니다.

## 기술 참고 사항

NoMenu는 Swift, SwiftUI, AppKit, macOS 손쉬운 사용 API, `NSStatusItem`, ScreenCaptureKit, Core Graphics 윈도우 정보, `SMAppService`를 사용합니다.

macOS에는 한 앱이 다른 앱의 `NSStatusItem` 소유권을 가져오거나 자유롭게 제어할 수 있게 해 주는 공개 API가 없습니다. 따라서 NoMenu는 상태 항목을 찾아 각 항목이 노출하는 손쉬운 사용 인터페이스를 통해 상호작용합니다. 타사 메뉴 막대 항목을 이동하거나 재정렬하거나 소유하지 않습니다.

소스 구성은 다음과 같습니다.

- `Sources/NoMenu/App` — 앱 및 패널 생명 주기
- `Sources/NoMenu/Services` — 항목 검색과 상호작용, 설정, 아트워크 캡처, 단축키
- `Sources/NoMenu/Views`, `Sources/NoMenu/Components` — 패널 및 설정 UI
- `Sources/NoMenu/Models` — 메뉴 항목 및 환경설정 모델
- `Resources`, `Support` — 앱 아트워크 및 번들 메타데이터
- `Tests` — 기능별 소스 수준 검사
- `scripts` — 패키징, 검증, 저장소 안전 검사 도구

## 알려진 제한 사항

- macOS 27부터 운영체제가 메뉴 막대 오버플로를 다른 방식으로 처리하므로 macOS 27 이상은 지원하지 않습니다.
- 검색과 상호작용은 각 앱이 노출하는 손쉬운 사용 역할, 위치, 메뉴와 동작에 따라 달라집니다. 사용자 정의 메뉴 막대 구현은 검색되지 않거나 일부 기능만 동작할 수 있습니다.
- NoMenu는 오버플로 상태를 신뢰할 수 있게 확인하지 못한 항목을 의도적으로 표시하지 않습니다.
- Live Artwork에는 화면 녹화 권한과 캡처 가능한 화면 픽셀이 필요합니다. 조건을 충족하지 못하면 캐시된 아트워크 또는 앱 아이콘이 표시될 수 있습니다.
- 공개 macOS API로는 다른 앱의 실제 `NSStatusItem` 객체에 접근할 수 없습니다.
- 현재 소스 스냅샷에는 위에서 설명한 빌드 검증 제한이 있습니다.

## NoMenu를 만든 이유

NoMenu는 앱 메뉴, 디스플레이 노치 또는 제한된 화면 구성 때문에 메뉴 막대 공간이 부족할 때 사라져 버린 상태 항목에 다시 접근하기 위해 시작되었습니다. 이후 macOS 27에 자체 오버플로 처리가 추가되면서 최신 시스템에서는 이 프로젝트가 해결하려던 원래 문제가 대부분 운영체제 기능으로 대체되었습니다.

## 기여

이 프로젝트는 현재 유지 관리·마무리 단계입니다. macOS 27 이전 동작에 관한 범위가 명확한 문제 제보나 변경은 환영하지만, macOS 27 이상 지원은 현재 개발 목표가 아닙니다.
