# NoMenu

[English](README.md) | **한국어**

NoMenu는 메뉴 막대에 사용할 수 있는 공간이 부족해 접근할 수 없게 된 항목을 다시 사용할 수 있도록 만든 macOS 유틸리티입니다. 손쉬운 사용 API를 통해 실제 상태 항목을 찾고, 오버플로된 것으로 확인된 항목만 자체 메뉴 막대 패널에 표시합니다.

> [!IMPORTANT]
> NoMenu는 macOS 27 이전 버전의 메뉴 막대 동작을 대상으로 설계되었습니다. macOS 27에는 시스템 자체의 메뉴 막대 오버플로 처리가 도입되어 NoMenu의 감지 기능이 의존하던 동작이 달라졌습니다. 따라서 macOS 27 이상은 지원하지 않습니다.

아래에서 소스 빌드 방법을 확인할 수 있습니다. 미리 빌드된 DMG가 준비되면 GitHub Releases를 통해 배포합니다.

## 다운로드

현재 공개된 DMG는 없습니다.

> 향후 미리 빌드된 DMG는 공식 바이너리 다운로드 위치인 [GitHub Releases](https://github.com/Rotear001/NoMenu/releases)를 통해 배포합니다.

향후 릴리스를 다운로드하기 전에 호환성을 확인해 주세요. NoMenu는 macOS 15–26을 대상으로 하며 macOS 27 이상은 지원하지 않습니다. 각 바이너리의 서명 및 공증 상태는 해당 릴리스 안내에 명시됩니다.

## 프로젝트 상태

NoMenu는 현재 유지 관리·마무리 단계입니다. 이 프로젝트가 해결하려던 원래 문제는 macOS 27의 자체 오버플로 기능으로 대부분 대체되었으므로 macOS 27 이상을 위한 기능 개발은 계획되어 있지 않습니다.

## 기능

- 실행 중인 앱이 macOS 손쉬운 사용 API로 노출하는 메뉴 막대 항목을 찾습니다.
- 손쉬운 사용 요소의 위치, 디스플레이 안전 영역, 현재 앱 메뉴가 차지하는 범위, 화면에 표시된 컴포지터 정보를 함께 사용해 항목을 표시됨, 오버플로됨, 확인 불가 상태로 분류합니다. 오버플로가 확인된 항목만 표시합니다.
- 지원되는 항목은 손쉬운 사용 동작을 통해 제어합니다. 읽을 수 있는 메뉴 트리가 있으면 NoMenu가 네이티브 프록시 메뉴를 표시하고 실제 메뉴 동작을 실행합니다.
- 패널에서 항목을 사용하는 동안 다른 항목으로 바로 전환할 수 있습니다.
- 메뉴 막대 순서, 최근 사용 순서 또는 이름순으로 항목을 정렬할 수 있습니다.
- 무시할 항목 관리, 전역 키보드 단축키, 포인터 오버 동작, Escape 키로 닫기, 항목 실행 뒤 패널 유지 옵션을 제공합니다.
- 패널 위치, 너비, 크기, 간격, 배경, 흐림, 투명도, 인터페이스 크기, 애니메이션과 영어·한국어 UI를 설정할 수 있습니다.
- `SMAppService`를 사용해 로그인 시 실행을 관리합니다.
- 프레임 속도를 설정할 수 있는 ScreenCaptureKit 기반 Live Artwork와 앱 아이콘 대체 표시를 제공합니다. Live Artwork는 화면 캡처 권한과 캡처 가능한 화면 픽셀에 따라 달라집니다.

## 호환성

| 항목 | 지원 범위 |
| --- | --- |
| 배포 대상 | macOS 15.0 |
| macOS 15–26 | NoMenu가 대상으로 삼은 기존 메뉴 막대 동작 범위 |
| macOS 27 이상 | 지원하지 않음 |

배포 대상 버전은 `Package.swift`와 `Support/Info.plist`에 정의되어 있습니다. 이는 빌드 대상의 하한을 뜻하며, macOS 15–26의 모든 버전과 모든 메뉴 막대 구현을 개별적으로 검증했다는 의미는 아닙니다.

빌드 도우미는 설치된 macOS 15–26 SDK가 필요하며 macOS 27 SDK는 의도적으로 사용하지 않습니다. 현재 선택된 Xcode 또는 Command Line Tools에서 가장 최신의 호환 SDK를 자동으로 선택합니다.

## 권한

### 손쉬운 사용

메뉴 막대 항목을 찾고, 해당 항목이 노출하는 메뉴 구조를 읽고, 지원되는 동작을 실행하려면 손쉬운 사용 권한이 필요합니다. 실제 동작은 각 타사 앱이 손쉬운 사용을 통해 제공하는 정보와 동작에 따라 달라집니다.

### 화면 및 시스템 오디오 녹음

화면 녹화 권한은 Live Artwork와 선택적 패널 모양에 쓰이는 데스크탑 배경 픽셀을 캡처하는 데 사용됩니다. 권한이 없으면 가능한 경우 캐시된 아트워크 또는 항목을 소유한 앱의 아이콘을 대신 표시합니다.

## 개인정보 보호

메뉴 막대 검색, 캡처한 아트워크 처리, 환경설정 저장은 Mac 안에서 이루어집니다. NoMenu 사용에 계정은 필요하지 않습니다. 현재 개발 빌드에는 업데이트 서비스 백엔드가 연결되어 있지 않습니다.

## 소스에서 빌드하기

NoMenu는 Swift 6 및 Swift Package Manager로 빌드한 뒤 실행 파일을 `LSUIElement` 앱 번들로 패키징합니다. 빌드하기 전에 macOS 15–26 SDK가 포함된 Xcode 또는 Xcode Command Line Tools를 설치하세요.

1. 저장소를 복제하고 해당 디렉터리로 이동합니다.

   ```sh
   git clone https://github.com/Rotear001/NoMenu.git
   cd NoMenu
   ```

2. [로컬 코드 서명](#로컬-코드-서명)의 설명에 따라 자신만의 로컬 서명 ID를 만든 뒤 확인합니다.

   ```sh
   ./scripts/check-local-signing.sh
   ```

3. 앱을 빌드하고 패키징합니다.

   ```sh
   ./scripts/build-app.sh release
   ```

   결과 앱은 `build/NoMenu.app`에 생성됩니다. `debug` 인자도 사용할 수 있으며 두 모드 모두 로컬 개발 빌드입니다.

4. 전체 빌드 및 앱 번들 스모크 검사를 선택적으로 실행할 수 있습니다.

   ```sh
   ./scripts/verify.sh
   ```

이 절차는 Apple Swift 6.4, macOS 26.5 SDK 및 개발자가 직접 만든 로컬 서명 ID로 검증했습니다. macOS 개인정보 보호 권한을 변경하거나 초기화하지 않습니다.

## 로컬 코드 서명

NoMenu는 손쉬운 사용을 비롯한 개인정보 보호 대상 API가 앱의 코드 식별 정보와 연관되기 때문에 개발 과정에서 안정적인 로컬 서명 ID를 사용합니다. 다시 빌드할 때마다 동일한 로컬 ID를 재사용하면 TCC 식별 정보가 반복해서 바뀌는 일을 줄일 수 있습니다.

개발자마다 **자신만의** 인증서와 개인 키를 만들어 보관해야 합니다. 표시 이름이 같아도 서로 다른 인증서이므로 다른 개발자의 서명 ID를 내려받거나 가져오면 안 됩니다.

키체인 접근에서 다음과 같이 서명 ID를 만드세요.

1. **키체인 접근**을 엽니다.
2. **인증서 지원**에서 **인증서 생성**을 선택합니다.
3. 이름을 **NoMenu Local Code Signing**으로 지정합니다.
4. **신원 유형**을 **자체 서명 루트(Self Signed Root)**로 지정합니다.
5. **인증서 유형**을 **코드 서명(Code Signing)**으로 지정합니다.
6. 새 ID를 자신의 로그인 키체인에 저장합니다.
7. 이후 NoMenu 개발 빌드에서도 자신이 만든 동일한 ID를 계속 사용합니다.

다음 중 한 가지 명령으로 확인할 수 있습니다.

```sh
./scripts/check-local-signing.sh
security find-identity -v -p codesigning
```

도우미는 유효한 서명 ID가 있는지만 확인합니다. 인증서나 개인 키를 생성·가져오기·내보내기하지 않으며 신뢰 설정도 변경하지 않습니다. 같은 이름의 ID가 없거나 여러 개인 경우 임의로 선택하지 않고 중단합니다.

이 로컬 ID는 Apple Developer ID 서명, 공증, Gatekeeper 승인, 공개 신뢰 또는 Apple 검증을 의미하지 않습니다. 개인 키, 키체인 내보내기 파일, `.p12` 파일, PEM 개인 키, 서명 암호 또는 컴퓨터별 서명 설정을 공유하거나 커밋해서는 안 됩니다.

## DMG 및 배포 참고 사항

이미 빌드한 앱을 로컬에서 다음 명령으로 패키징할 수 있습니다.

```sh
./scripts/package-dmg.sh
```

스크립트는 실제 앱 버전을 읽어 `dist/NoMenu-<version>.dmg`를 만들며, DMG에는 `NoMenu.app`과 Applications 바로 가기만 포함됩니다. DMG와 앱 번들은 Git에서 무시되며 일반 저장소 이력에 커밋하면 안 됩니다.

로컬 자체 서명 DMG는 Apple 공증, Developer ID 서명, Apple 검증 또는 Gatekeeper의 자동 신뢰를 받은 파일이 아닙니다. 향후 공증되지 않은 릴리스가 macOS에서 차단되면 앱을 Control-클릭한 뒤 **열기**를 선택하거나 **시스템 설정 › 개인정보 보호 및 보안**에서 해당 앱을 검토하는 Apple의 앱별 승인 절차를 사용하세요. Gatekeeper, SIP 또는 다른 macOS 보안 기능을 끄면 안 됩니다.

공개 DMG는 [GitHub Releases](https://github.com/Rotear001/NoMenu/releases)에 `NoMenu-<version>.dmg` 자산으로 올려야 합니다. 릴리스 생성과 공개는 별도의 배포 작업이며 저장소의 로컬 개발 인증서와 개인 키는 절대 포함하면 안 됩니다.

## 기술 참고 사항

NoMenu는 Swift, SwiftUI, AppKit, macOS 손쉬운 사용 API, `NSStatusItem`, ScreenCaptureKit, Core Graphics 윈도우 정보, `SMAppService`를 사용합니다.

macOS에는 한 앱이 다른 앱의 `NSStatusItem` 소유권을 가져오거나 자유롭게 제어할 수 있게 해 주는 공개 API가 없습니다. 따라서 NoMenu는 상태 항목을 찾아 각 항목이 노출하는 손쉬운 사용 인터페이스를 통해 상호작용합니다. 타사 메뉴 막대 항목을 이동하거나 재정렬하거나 소유하지 않습니다.

소스 구성은 다음과 같습니다.

- `Sources/NoMenu/App` — 앱 및 패널 생명 주기
- `Sources/NoMenu/Services` — 항목 검색과 상호작용, 설정, 아트워크 캡처, 단축키
- `Sources/NoMenu/Views`, `Sources/NoMenu/Components` — 패널 및 설정 UI
- `Sources/NoMenu/Models` — 메뉴 항목 및 환경설정 모델
- `Resources`, `Support` — 앱 아트워크 및 번들 메타데이터
- `Tests` — 기능별 소스 수준 검사
- `scripts` — 서명 검사, 빌드, 패키징, 검증, 저장소 안전 검사 도구

## 알려진 제한 사항

- 운영체제가 메뉴 막대 오버플로를 다른 방식으로 처리하는 macOS 27 이상은 지원하지 않습니다.
- 검색과 상호작용은 각 앱이 노출하는 손쉬운 사용 역할, 위치, 메뉴와 동작에 따라 달라집니다. 사용자 정의 메뉴 막대 구현은 검색되지 않거나 일부 기능만 동작할 수 있습니다.
- NoMenu는 오버플로 상태를 신뢰할 수 있게 확인하지 못한 항목을 의도적으로 표시하지 않습니다.
- Live Artwork에는 화면 녹화 권한과 캡처 및 합성이 가능한 화면 픽셀이 필요합니다. 조건을 충족하지 못하면 캐시된 아트워크 또는 앱 아이콘이 표시될 수 있습니다.
- 공개 macOS API로는 다른 앱의 실제 `NSStatusItem` 객체에 접근할 수 없습니다.

## NoMenu를 만든 이유

NoMenu는 앱 메뉴, 디스플레이 노치 또는 제한된 화면 구성 때문에 메뉴 막대 공간이 부족할 때 사라져 버린 상태 항목에 다시 접근하기 위해 시작되었습니다. 이후 macOS 27에 자체 오버플로 처리가 추가되면서 최신 시스템에서는 이 프로젝트가 해결하려던 원래 문제가 대부분 운영체제 기능으로 대체되었습니다.
